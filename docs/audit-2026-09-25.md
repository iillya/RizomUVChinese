# RizomUV 汉化审查记录 — 2026-09-25

## 范围与结果

审查运行时初始化、GDI 导入接入与文字替换、原生菜单和署名窗口、JSON 词典加载、启动器、安装卸载及打包脚本。保留既有汉化方式和正式词条，按职责整理，不把多个功能塞入一个大文件。

本轮可确认问题已修复并重新构建，审查修复随 1.0.4 版发布。此记录不等于所有软件版本、所有界面和复杂工程均完成验收。

## 修复

| 问题 | 处理 |
| --- | --- |
| JSON 可接受重复键、尾逗号、非法元数据或孤立代理字符 | 严格解析、UTF-8/UTF-16 校验，限制文件为 64 MiB、元数据递归深度为 64；加载失败不替换已有词典；打包前也检查词典 |
| 长译文和递归绘制使用同一临时译文缓冲 | 词典初始化后只读，直接引用稳定译文；每线程复用查找缓冲，分配失败退回原文 |
| DrawTextW 可写缓冲标志未保护 | 与 DrawTextExW 一样绕过 DT_MODIFYSTRING；保留字形索引、逐字符测量数组、非法计数和未命中时原始参数 |
| 项目路径被误当宿主程序、反斜杠和引号转义不完整 | 识别显式 rizomuv.exe 参数，其余参数传给对应安装；按 Windows 参数规则转义，并做往返测试 |
| 启动失败信息写入不可见控制台、异常可能留下挂起进程 | 改为错误对话框；进程句柄统一释放，失败时终止本次创建的进程；拒绝 x86 目标 |
| LoadLibraryW 可能被系统转发 | 计算实际所属模块中的偏移，按对应远程模块定位；保留新建挂起进程的兼容回退路径 |
| 开发启动器硬编码查找 2025 | 正常安装按启动器相对位置找宿主，开发测试显式指定程序路径 |
| 旧版宿主可能缺少新版 VC 运行库 | 运行时、启动器静态链接 MSVC 运行库；依赖检查只出现 Windows 系统 DLL |
| 顶部署名缩窄后残留、DPI 变更、频繁位置消息 | 空间不足/主窗口隐藏时隐藏链接；重算 DPI，合并待处理消息；部分创建失败清理窗口，退出时解除事件钩子 |
| 原生菜单重复重绘、过长标签截断风险 | 仅实际翻译成功时重绘，限制递归层数，跳过截断/自绘项文本，但继续遍历其子菜单 |
| 日志目录可能不可写、文件长期增长 | 不可写时回退 LocalAppData；超过约 256 KiB 在下次初始化时保留一个旧日志 |
| 安装器残留无效的其他产品功能 | 删除未配置的文件关联代理、旧关联迁移、Qt/字体适配及四个失去引用的头文件；保留目录/进程/链接检查 |
| 文档与实际更新卸载行为冲突 | 按用户流程重写 README，明确覆盖更新替换词典、卸载完整删除 ChineseLauncher；开发细节移入独立文档 |

后台仍每两秒检查一次宿主目录中的已加载模块，以保留后加载 DLL 和已解析延迟导入的兼容性。没有为了节省扫描而删掉这些覆盖路径。绘制回调不访问磁盘或网络。

## 词典

从本地 2018、2022 原始安装器内的程序及已安装的 2025 程序中筛查候选，排除 FBX 内部属性路径、库调试文字、代码符号等，人工补译 322 条。

- 原有 3,806 条键和值全部保留，没有删除或覆盖。
- 新词典共 4,128 条，无空白译文、无重复 JSON 键、无 Unicode 替换字符。
- 主要增加 UV 集、岛组、边选择、排布、导出设置及提示说明。
- 该数量代表词典映射数量，不能据此声称所有 UI 已翻译。扫描候选也不能仅凭出现在二进制中就认定为 UI。
- 本地溯源：`build/audit-dictionary-additions.json`。该文件为审查产物，不作为第二份运行时词典加载。

## 验证

- VS 2022 x64 Release 编译通过；最终构建无编译警告。
- 回归程序通过：普通/延迟导入、缺少名称表、DLL 别名、边界与架构、Unicode/重复 JSON 键/非法结构、Windows 参数转义、递归查找结果有效性。
- GDI 回归用“ABC → 更长的中文测试”的有效词典验证测量数组边界、字形索引及 DrawTextW/ExW 可写缓冲保护，避免在空词典下产生假通过。
- 正式词典用运行时 C++ 解析器实读，返回 4,128 条。
- 隔离安装、修改词典后覆盖更新、完整卸载均成功；安装载荷哈希匹配；额外补丁目录文件随卸载删除，外部哨兵文件和原始宿主保留。
- 安装器目录检查：正常 x64 测试宿主通过；磁盘根目录、缺少宿主的目录、仍在运行的实际宿主目录拒绝。
- 2025.0.104 启动成功，日志确认 4,128 条、4 个 GDI 导入入口、7 次原生菜单翻译操作及绘制翻译命中，进程有响应。
- 两次本机启动中，前五次常驻模块扫描的平均墙钟耗时分别为 689、726 微秒，每两秒执行一次。该值只描述该机器该次扫描，不代表完整软件 CPU/GPU 占用，也不是复杂工程性能保证。
- 微基准中，20 万次查找（10 万命中、10 万未命中；小型测试词典）约 4.5–5.4 毫秒，不能当作真实界面帧时间。

## 尚需实际界面验证的边界

1. 2018.0.222、2022.1.57 仅检查原始程序的 x64 架构及公开 GDI 导入，没有运行全部界面。两版所需四个入口与已测 2025 相同，但不足以证明布局与覆盖率一致。
2. 署名位置仍根据菜单文本估算，旧版菜单排列、自定义布局、不同缩放可能导致偏移。缩窄时隐藏只能避免越界，不能证明所有版本定位准确。
3. 使用 DirectWrite、OpenGL 字形、自定义渲染、逐字符测量的文字可能不经过当前安全替换路径。原生菜单的专门扫描限于启动阶段，新建菜单若不经过已有绘制路径仍可能漏译。
4. 固定大小控件、逐字符排版及动态拼接文字可能有截断或漏译。现有词典按完整文字匹配，同名文字也无法区分每个界面语境。
5. 尚未进行各版本复杂工程的展开、排布、导出和长时间稳定性验收；本轮没有改动这些算法和文件内容。
