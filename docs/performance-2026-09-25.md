# 性能复查 — 2026-09-25（v1.0.4 合并更新）

## 结论

现有后台开销已较小，主要可优化项在高频文字查找和不必要的界面事件处理。本轮已实现、编译并完成回归与启动验证，合并更新到现有 v1.0.4，使用同一个 Release 和安装包下载入口。

## 已实施

1. **查词不复制原文。** 采用 C++20 异构哈希查找，以 `wstring_view` 查询持有自身字符串的只读词典。删除线程局部英文缓冲；不会保留宿主的临时文本指针，也不新增无界命中/未命中缓存。原有大小写、空格、CJK/路径过滤和原始字符计数语义保持不变。
2. **命中统计只用于启动诊断。** 启动扫描结束后关闭统计写入。常态命中只读取标志，不再每次执行共享原子计数。没有减少实际翻译次数。
3. **减少署名定位消息。** 只处理主窗口自身及客户区的相关事件，忽略其他控件和光标事件；继续合并同一时段的位置消息，保留移动、缩放、显示/隐藏、最小化和 DPI 路径。
4. **减少扫描的附带开销。** 路径缓冲不再为每个模块清零 64 KiB，系统模块不再无条件增加/释放引用。应用模块在取得引用后再次确认路径，通过作用域对象释放引用，防止异常时漏释放。按后续确定的策略，仅在启动后前 120 秒内以两秒间隔遍历普通与延迟导入，不缓存可能失效的模块地址或导入槽。
5. **减少启动菜单临时对象。** 使用字符串视图切分标签，原文和译文相同时不重复写菜单或重绘。

运行时和测试改用 C++20，启动器仍使用 C++17。二进制依赖核对仍只有 USER32、GDI32、SHELL32、KERNEL32，没有引入新的 VC 或第三方运行库依赖。

## 测量方法与结果

使用正式词典全部 4,128 个键生成固定语料，保留空格、换行与大小写。每项循环 60 次、测量七轮取中位数；旧二进制来自本次修改前的 v1.0.4 源码，新二进制包含以上修改。时间包括筛选、查词和统计路径，不包括 Windows 实际绘字。

| 场景 | 修改前第 1 / 2 组 | 修改后第 1 / 2 组 | 单位与解释 |
| --- | --- | --- | --- |
| 短词命中，2,537 个键 | 82 / 107 | 82 / 80 | ns/次，单线程；波动明显，不宣称固定收益 |
| 长提示命中，187 个键 | 1,118 / 1,134 | 1,054 / 1,057 | ns/次，单线程；耗时降低约 6%–7% |
| 混合未命中，4,128 个键 | 239 / 250 | 236 / 236 | ns/次，单线程；改善有限 |
| 混合命中，四线程 | 76 / 85 | 61 / 66 | 总墙钟时间除以总查询数，衡量吞吐而非单线程延迟；耗时降低约 20%–22% |

新旧词典加载约 5–6 ms，属于一次性启动成本，差异不足以判断加载优化收益。

本机 RizomUV 2025.0.104 新版启动日志：4,128 个词条、4 个 GDI 接入口、7 次原生菜单翻译、8,597 次启动阶段命中；进程有响应。常驻模块扫描前五次平均 **707 微秒/次**，每两秒执行一次；此前测得 689、726 微秒，差异属于噪声，**不把这项报告为实际加速**。

这些数据不能换算成整个 RizomUV 的提速百分比，不能代表复杂模型展开、排布、GPU 渲染或所有旧版本性能。

## 回归覆盖

- 正式语料中的每个键均核对预期译文及原有排除规则。
- 非空终止字符串切片查找、原文不复制时的长度匹配、递归调用后的译文有效性。
- 启动计数关闭后，翻译继续生效且统计不再写入。
- 20,000 次无关署名事件不入队；10,000 次主窗口位置事件合并为一条；客户区事件仍可触发。
- 菜单翻译保留快捷键文本，已翻译菜单再次扫描不重复修改。
- 原有 JSON 异常输入、参数转义、GDI 可写缓冲/字形索引/输出数组、普通和延迟导入等测试继续通过。

模拟事件测试并不等于所有显示缩放和多显示器配置的人工验收。

## 全部路径的审查判断

| 路径 | 判断 |
| --- | --- |
| GDI 绘制与测量 | 已实施无原文复制和常态计数停止；保留安全绕过与六个入口 |
| 词典驻留内存 | 一份只读映射；没有逐帧增长的结果缓存。删除的旧查找缓冲曾按每线程见到的最长文本保留容量，并非已证明存在内存泄漏 |
| 模块检测 | 每次约 0.7 ms；仅前 120 秒扫描，到期后线程退出。已接入汉化保留，之后新加载/解析的接口不再补接 |
| 原生菜单 | 40 次启动扫描结束后停止，不是常驻全窗口轮询；已减少临时分配和同值重绘 |
| 署名绘制 | 平时按事件工作，尺寸未变化时仅移动；位图、字体和 DC 均释放，无每帧全屏抓取。隐藏后再次显示时重建少量资源，暂不增加缓存复杂度 |
| 日志 | 绘制回调不写日志；模块已有接入不重复记录。日志在启动时轮换，未发现需要引入异步日志线程的必要性 |
| 启动器与安装器 | 不属于汉化常驻后台；没有轮询、网络翻译或安装器守护进程 |

按用户要求，后台检测改为启动后最多 120 秒；不减少汉化入口，不跳过长提示。若后续真实工程出现卡顿，应先采样确认耗时位于哪条绘制路径；再评估有限大小的重复文本缓存，而非现在引入失效、内存和命中率成本。

## 后续扫描时限调整

120 秒从运行时初始化入口计时，包含菜单扫描阶段，不是初始化结束后再额外扫描 120 秒。休眠醒来后再次检查截止时间，截止后不启动新的模块扫描；写入结束日志后工作线程返回。已接入的绘制 Hook、词典和事件驱动的署名继续生效。
