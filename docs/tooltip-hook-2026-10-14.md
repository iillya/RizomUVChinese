# HTML 提示路径修复记录

## 问题

用户截图中的 `Lets you select and work at edge level` 已存在于正式词典，本机安装词典与当时的补词后源词典哈希也一致，但正文仍显示英文。单纯补词没有覆盖提示的整句处理路径。本次修复归入正式版 1.0.5。

本机 2027.0.598 程序的 RTTI 含 `CToolTipHtmlWindow`、`CToolTipPopup` 和 `wxHtmlWordCell`。离线反汇编确认，提示尺寸计算三次通过 `0x748` 虚表偏移调用 SetPage，即第 233 个槽；原方法在 `0x068bc980` RVA。该方法先清理打开页面、锚点和标题，再进入 HTML 解析。wxHTML 后续以词单元绘制，GDI 端拿到的文本可能不是词典中的完整说明。

参考：[wxHtmlWindow 的 SetPage 实现](https://github.com/wxWidgets/wxWidgets/blob/master/src/html/htmlwin.cpp)、[wxHtmlWordCell 绘制实现](https://github.com/wxWidgets/wxWidgets/blob/master/src/html/htmlcell.cpp)。上游源码用于解释流程；本机入口偏移及 ABI 以本机程序的实际反汇编为依据。

## 修复

- 在提示子类的 SetPage 入口翻译 HTML 正文，先翻译整句，再交回宿主完成拆词、测量及排版。普通 GDI 接口继续用于其他 UI。
- 只补接提示子类的虚表槽，不改写函数指令，不给所有 HTML 窗口安装全局替换。
- 解码正文中的 HTML 实体、统一匹配用空白；保留 HTML 标签、属性、链接目标、表格结构和快捷键。译文重新转义，避免把文字当作 HTML。
- 对被内联格式标签拆开的已收录整句，合并正文查词后保留原标签。双语无法可靠逐词对齐，译文不保证继承原句每个词的粗体/斜体位置；标题整体的外层样式保留。
- 未收录正文、未知实体、畸形 HTML、script/style/head 内容及规范化后有冲突的词条不猜译。保持未知文本原样。
- 临时 wxString 使用宿主的复制构造和清理入口，原始 const 字符串不改写；原方法失败时不重复调用，异常路径也清理临时对象。
- 词典与规范化查词表初始化后只读；不在每帧扫描窗口，不在绘制或提示回调中读写日志或联网。启动后 120 秒停止扫描的约束保留。
